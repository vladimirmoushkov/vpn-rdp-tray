# Security

## Authenticator codes and optional passwords

When you choose automatic TOTP, the app protects the seed separately with DPAPI `CurrentUser` inside the encrypted setup file. It decrypts the seed just long enough to generate a code and clears the mutable seed buffer afterward. Generated or manually entered codes are used in memory. Setup displays an empty, masked field for a saved seed. Clear automatic generation and save to remove the active copy. An upgrade migrates legacy seeds that are still present. Older backups or copies can retain the seed. [TOTP requirements](https://www.rfc-editor.org/rfc/rfc6238) · [Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)

VPN password, VPN private key passphrase and classic RDP password each have a separate save option. All three start off in new setups. An upgrade keeps existing saved passwords so you can decide which ones to remove. Clear the corresponding checkbox and click **Save** to remove an app-saved password. If you choose to save one, the app encrypts it for the signed-in Windows account using DPAPI `CurrentUser`. Under ordinary conditions Windows requires the same account to decrypt it. Software running as your account or an administrator who controls the endpoint can still access it. [Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)

An automatic client needs access to the seed. Code running under the same Windows account can decrypt it. Saving both factors puts both within reach of a compromise of that account. For independent factors use manual codes from a separate authenticator and leave password saving off. Use a managed Windows device with current patches and disk encryption. For RDP, prefer native Microsoft Entra sign-in with the organization’s MFA and Conditional Access policy. Windows manages any credentials you separately choose to remember in a native sign-in dialog. [Microsoft guidance on handling passwords](https://learn.microsoft.com/en-us/windows/win32/secbp/handling-passwords) · [Microsoft Entra RDP requirements](https://learn.microsoft.com/en-us/windows-server/remote/remote-desktop-services/remotepc/remote-desktop-connection-single-sign-on)

If a password, enrolled TOTP seed, client private key, or associated profile is disclosed, notify the VPN administrator. Rotate the password, revoke and re-enroll the authenticator, or revoke and reissue the affected client certificate as appropriate. Update Setup with the replacement values. Treat the original exports, recovery codes, and enrollment screenshots as confidential. [GitHub guidance on rotating exposed credentials](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)

## Credential and connection handling

- `%LOCALAPPDATA%\VpnRdpTray\setup.dpapi` contains the protected VPN and RDP settings, imported certificate and private key material, and any opt-in passwords and TOTP seed. Saving uses a protected temporary file and an atomic replacement. Saved credentials stay out of Setup’s text fields. Uninstall removes the app’s active configuration.
- The tray app decrypts the file when starting a connection, opening Setup, or checking for a legacy seed. It clears mutable buffers containing the decrypted configuration and encoded authentication commands after use. Managed strings, Windows controls and OpenVPN can retain recently used values in memory until reclaimed. Restrict access to the Windows session, its memory, and crash dumps.
- The administrator-approved launcher on disk contains a named-pipe reference. The imported profile is streamed over a current-user pipe after checking the OpenVPN child process ID. The app verifies the Interactive Service pipe against Windows Service Control Manager, limits the management listener to loopback, checks the connecting process, and uses a random per-launch management password supplied over service stdin. VPN passwords and one-time codes go over this local connection. The app has no telemetry or stored raw OpenVPN log. [OpenVPN Interactive Service protocol](https://github.com/OpenVPN/openvpn/blob/v2.7.9/doc/interactive-service-notes.rst) · [OpenVPN management protocol](https://github.com/OpenVPN/openvpn/blob/v2.7.9/doc/management-notes.txt)
- Import profiles from the VPN administrator. The importer allows supported client directives, enforces TLS 1.2 or later, rejects compression and requires an exact server certificate name with CA validation or a SHA-256 certificate fingerprint. Use SHA-256 fingerprints verified through a trusted channel. The retry controller limits repeated credential submissions, pauses on certificate failures, and persists the rejection budget across restarts. Set the budget to the administrator’s lockout policy. [OpenVPN 2.7 manual](https://openvpn.net/community-docs/community-articles/openvpn-2-7-manual/)
- The Windows RDP control uses NLA/CredSSP and requires server certificate validation. The application checks DNS results and routing before opening RDP and stops its session when the tunnel is lost. The Windows RDP client can resolve a hostname again and the operating system can change routes after the check. If network policy requires enforced tunnel-only egress, apply it at the firewall or on the network. [Windows RDP authentication level](https://learn.microsoft.com/en-us/windows/win32/termserv/imsrdpclientadvancedsettings4-authenticationlevel)
- Remote Desktop redirection grants the remote computer access to enabled resources. Review the default-on choices in **Setup → Remote Desktop** and disable resources you do not need. Windows and remote-host policy also apply. [Microsoft’s redirection security guidance](https://learn.microsoft.com/en-us/windows-server/remote/remote-desktop-services/remotepc/understanding-security-warnings#understanding-redirections)
- **Simulate activity** is an explicit opt-in for a signed-in embedded session. The app sends only a paired Shift input through that session’s Windows control. Keep it off on hosts where policy requires inactive sessions to close. [Embedded RDP input API](https://learn.microsoft.com/en-us/windows/win32/termserv/imsrdpclientnonscriptable-sendkeys)

## Local metadata and administrator access

The temporary native `.rdp` file contains connection settings, including the hostname and account name. The app removes it on normal teardown and cleans its leftover file on startup. Native Windows logs and the RDP client may keep their own history. An opt-in hosts entry contains the hostname, IP address and a Windows account SID tag. Windows command or script auditing may record these values when the elevated helper updates the file. Prefer trusted VPN DNS when available.

The tray runs as the signed-in standard user. Installing OpenVPN or changing machine configuration is an explicit step that uses administrator approval. The built-in OpenVPN installer download is pinned to the SHA-256 of the official Windows package. The app verifies it again from an open package handle and holds the package and its local directory path against replacement during installation. [Official OpenVPN packages](https://community.openvpn.net/Downloads)

## Report a vulnerability

Use the repository’s **Security → Report a vulnerability** form. Include the app version, affected Windows and OpenVPN versions, expected behavior and a reproduction with synthetic accounts and endpoints. Keep `.ovpn` profiles, protected setup files, host mappings, keys, TOTP enrollment material, dumps and personal or company identifiers out of reports. Report an exposed credential to its issuing organization as well. [GitHub private vulnerability reporting](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository)
